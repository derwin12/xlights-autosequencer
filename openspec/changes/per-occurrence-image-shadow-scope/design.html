OpenSpec design · per-occurrence-image-shadow-scope

Design: scope Unmap/Shadow to a single lyric occurrence

Make the Pictures screen's Unmap and Shadow actions apply to the one lyric occurrence clicked — not every occurrence of that word in the whole song — matching the granularity the UI already displays (each row has its own timestamp) but the action never respected.

The problem

A real song ("Dream On") shows 9 separate "DREAM" rows at distinct timestamps (3:02 through 3:18), each independently matched to dream2.png. Clicking Unmap or Shadow on any one of them acts on the word text, not that row — every occurrence changes at once.

Root cause: ignored_image_words / shadow_text_words (GenerationConfig, session JSON, and the matching logic in image_catalog.suggest_images_for_words / effect_placer._place_shadow_text_effects) have always been flat list[str] word tokens. The display data (image_topics/imageSuggestions) was already per-occurrence — only the action layer collapsed everything to word-level.

Approach

Rename and reshape both fields — a genuine shape change, not additive. Renaming (rather than keeping the old name with a new meaning) forces every caller to be touched deliberately instead of silently misinterpreting the new shape.

BeforeAfter
ignored_image_words: list[str] ignored_image_occurrences: list[dict] — each {"word", "start_ms"}
shadow_text_words: list[str] shadow_text_occurrences: list[dict] — same shape
Backend

Storage + API

  • POST /songs/<id>/ignored-images body gains start_ms
  • DELETE /songs/<id>/ignored-images/<word>/<start_ms> — path gains a segment (a compound key needs both parts)
  • Same two changes mirrored for /shadow-words
  • Session JSON key renamed to match
Generator

Occurrence-aware matching

# before: token-only set
ignored = {w.lower() for w in (ignored_words or [])}
...
if token in ignored: continue

# after: (token, start_ms) tuple set
ignored_pairs = {(o["word"].lower(), o["start_ms"]) for o in (ignored_occurrences or [])}
...
if (token, word.get("start_ms")) in ignored_pairs: continue

Same shape of change in _place_shadow_text_effects's spans filter. GenerationConfig, plan.py's two call sites, generator_runner.py, and export.py get mechanical renames.

Frontend

Pictures.tsx — composite key

ignored/shadowWords state becomes Set<string> keyed by `${word.toLowerCase()}|${start_ms}` instead of plain word — 6 call sites across 3 sections (Already matched, Suggested topics, uploaded) updated to build/check that key. ignoreMatch/toggleShadowWord both gain a start_ms parameter. activeSuggestions' filter keys off the composite identifier so unmapping one row only moves that row, leaving siblings mapped.

What does NOT change

  • lyricWordCandidates's word-level dedup (the "Suggested topics" empty-state list) — unrelated, stays as-is.
  • "Choose image"/upload-per-word behavior — not requested; a materially different feature (the library tag is shared, not per-occurrence).
  • How image_topics/imageSuggestions are computed — already per-occurrence; only the action layer changes.

Alternatives considered

OptionRejected because
Keep old field names, just reshape their contents A list[str] silently becoming a list[dict] under the same name produces confusing failures far from the mistake (e.g. a stale "word" in old_list check silently always-False). Renaming forces every caller to be touched deliberately.
Auto-migrate old word-level ignores into per-occurrence entries at load time The old data was itself a symptom of this bug — the user never wanted "ignore everywhere," the tool only offered that granularity. Auto-expanding it forward would reproduce today's wrong scope one more time. Per-song state resets once instead.
Add a new parallel per-occurrence field, keep the old one for back-compat Two overlapping mechanisms for nearly the same thing — exactly what CLAUDE.md's "don't over-engineer" / no-shims principle warns against.

Regression surface

  • Verified: suggest_images_for_words has two other call sites (image_catalog.py's own find_unmatched_topics, analysis.py's analyze-phase suggestion computation) — neither passes ignored_words at all, so the rename doesn't touch their behavior. Only plan.py (generation time) passes it.
  • _place_shadow_text_effects is private with a single call site (plan.py), already covered.
  • GenerationConfig's two renamed fields: grep confirms writers (export.py, generator_runner.py) and the one reader (plan.py) are all in the files-touched table — nothing else constructs GenerationConfig with the old names.

Validation

  1. Unit: updated tests per the files-touched table; full pytest tests/unit/test_generator tests/review -v.
  2. Frontend: new test — unmap one "DREAM" occurrence, assert the other 8 rows are unaffected and the unmapped one moves to "Suggested topics."
  3. Manual: reproduce the exact reported scenario against the real song, confirm one Unmap only removes that timestamp's mapping.
